## Оценка перехода на FastAPI

### Плюсы

| | |
|---|---|
| **Скорость для пользователя** | Один запрос `/heroes` вместо 30+ к API — главная грузится заметно быстрее |
| **Контроль данных** | Нормализация, кеш, fallback — на сервере, фронт получает готовый JSON |
| **Новые фичи** | Популярные билды, мета-аналитика, свои заметки, голосования — без ограничений публичного API |
| **Безопасность** | API-ключи, rate limit, закрытый прокси — не светятся на клиенте |
| **Масштабирование** | Redis, фоновые задачи, своя БД (PostgreSQL) для юзерских данных |

### Минусы

| | |
|---|---|
| **Стоимость и поддержка** | VPS от ~300–500 ₽/мес + время на администрирование |
| **Сложность** | Два деплоя, мониторинг, логи, бэкапы — больше moving parts |
| **Latency** | Лишний hop (фронт → твой сервер → deadlock-api), если кеш промахнулся |
| **Зависимость от API** | Deadlock API может измениться — чинить придётся на бэкенде |
| **Overkill на старте** | Для статичного справочника текущая архитектура уже работает |

### Вердикт

**Переделать будет удобно** — проект уже подготовлен к этому:

- слой `api/` отделён от UI;
- `config.js` с режимом `backend` и `ENDPOINTS`;
- `heroService.js` — чистая доменная логика, переносится в Python почти 1:1;
- Zustand-сторы не привязаны к источнику данных.

Рекомендуемый порядок:

1. Сейчас — фиксы из раздела «Баги» + вынести DTO-контракты.
2. При появлении сервера — FastAPI с 3 эндпоинтами (`heroes`, `heroes/{id}`, `items`).
3. Переключить `VITE_API_MODE=backend`, убедиться что фронт работает.
4. Добавить Redis, фоновый кеш, новые фичи (билды, мета-дашборд).

Не переписывай всё сразу — **постепенная миграция по эндпоинтам** самый безопасный путь.
